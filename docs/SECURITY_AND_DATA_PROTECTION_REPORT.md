## 2. Multi-Tenant Data Isolation

### 2.1 Logical Isolation Enforcement
Multi-tenancy in CloseCraft is enforced logically via non-nullable `organizationId` foreign keys on all business records. Direct client access to database identifiers without tenant validation is impossible:
1. Every authenticated session resolves the user's active `organizationId` from database membership.
2. Every server action, API route, and background worker explicitly scopes queries with `{ where: { organizationId } }`.
3. Cross-tenant access attempts immediately evaluate to null or return HTTP 403 Forbidden.

### 2.2 Verified Isolation Test Evidence
In `tests/data_privacy_and_security_acceptance.test.cjs`, strict isolation was verified between two simulated organizations (`Alpha Enterprises` and `Beta Industries`):
- Cross-tenant queries by Tenant B attempting to read Tenant A's leads returned `null`.
- Cross-tenant update attempts resulted in zero rows modified.
- Audit logs generated by Tenant A were completely invisible to Tenant B.

## 3. Statutory Privacy Compliance (NDPA & GDPR)

CloseCraft provides comprehensive compliance mechanisms aligned with Section 24 of the **Nigeria Data Protection Act (NDPA 2023)** and Articles 15, 17, and 20 of the **EU GDPR**.

### 3.1 Right to Data Portability (Data Export)
- **Endpoint:** `GET /api/privacy/export?leadId={id}`
- **Operation:** Exports an authenticated prospect's complete personal profile, conversation transcripts, commitment records, orders, and interaction history as a structured JSON portability package.
- **Access Control:** Requires authenticated user membership in the data controller's organization.

### 3.2 Right to be Forgotten (Atomic Data Erasure)
- **Endpoint:** `POST /api/privacy/delete`
- **Operation:** Executes atomic data erasure across all linked records (Messages, Conversations, Intelligence, Commitments, Orders, and Lead profile).
- **Compliance Audit Record:** Retains an anonymized compliance record in `AuditLog` stating the resource type, timestamp, and legal erasure justification while wiping all personally identifiable information (PII).

### 3.3 Consent Management & Marketing Opt-Out
- **Keyword Suppression:** Prospects who reply with `STOP`, `UNSUBSCRIBE`, `REMOVE ME`, or `STOP MESSAGING` on WhatsApp or web chat are immediately flagged (`optedOutOfMarketing: true`).
- **Outbound Prevention:** Outbound dispatch via `sendWhatsAppMessage` and `dispatchReactivationCampaign` validates opt-out status prior to transmission. Opted-out leads are automatically suppressed.
- **Cookie Consent:** Integrated cookie banner (`src/components/layout/CookieConsent.tsx`) ensures explicit consent for analytics and session tracking.

## 4. Webhook Security & Tamper Resistance

### 4.1 Meta Webhook Signature Verification
- Inbound WhatsApp and Facebook webhooks transmit an `x-hub-signature-256` HTTP header containing the HMAC SHA-256 signature of the payload using the `META_APP_SECRET`.
- The webhook endpoint computes the expected hash against the raw request buffer:
```typescript
const signature = req.headers.get('x-hub-signature-256');
const expected = 'sha256=' + crypto.createHmac('sha256', appSecret).update(rawBody).digest('hex');
if (!crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected))) {
  return new Response('Invalid Signature', { status: 401 });
}
```
- Timing-safe comparisons prevent timing-attack exploits.

### 4.2 Idempotency & Replay Defense
- Provider message identifiers (`wamid.xxx`) are tracked in database message records.
- Incoming webhook events matching existing provider IDs are acknowledged with HTTP 200 without duplicate processing.

## 5. Vulnerability & Secret Management

- **No Secrets in Source:** No private credentials, tokens, or database connection strings are committed to the repository. All secrets are injected via encrypted environment variables.
- **Client Boundary Protection:** Sensitive credentials (`META_APP_SECRET`, `PAYSTACK_SECRET_KEY`, `OPENAI_API_KEY`, `DATABASE_URL`) are strictly restricted to Node.js server environments and never exposed to client bundles.
